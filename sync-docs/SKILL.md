# Git 文档同步命令

执行以下工作流程，同步 git 修改到项目文档。

## Phase 1: 获取修改内容

首先获取当前 git 修改状态：

```bash
git status --porcelain
git diff --stat
git diff --numstat
```

如果工作区干净，检查最新一次 commit：

```bash
git log -1 --stat
git show --name-only HEAD
```

## Phase 2: 分析影响范围

根据修改的文件路径，识别涉及的目录：

- 提取所有修改文件所在的目录
- 对每个目录向上查找，直到找到有业务意义的模块目录
- 识别需要处理的目标：
  - 目录存在 MODULE.md → 更新
  - 目录不存在 MODULE.md → 创建
  - 目录被删除 → 删除对应的 MODULE.md
  - 项目根目录 AGENTS.md → 检查是否需要更新

## Phase 3: 分析修改内容并判断更新类型

**必须读取 git diff 的具体内容，分析修改语义，而非仅靠行数判断。**

### 3.1 获取修改内容

```bash
# 获取完整的 diff 内容
git diff

# 如果有暂存的修改
git diff --cached

# 如果工作区干净，查看最新 commit 的修改
git show HEAD
```

### 3.2 分析修改内容

对每个修改的文件，分析以下内容：

1. **修改了什么**：
   - 新增了哪些函数/类/接口
   - 删除了哪些函数/类/接口
   - 修改了哪些函数签名
   - 修改了哪些业务逻辑
   - 修改了哪些配置项

2. **修改的影响范围**：
   - 是否影响对外暴露的接口（export/public）
   - 是否影响模块间的调用关系
   - 是否改变业务流程或规则
   - 是否引入新的依赖或移除依赖

### 3.3 判断更新类型

**内容级更新**（需要更新契约内容）：

- 新增/删除/修改了对外暴露的函数或接口
- 改变了模块的职责边界
- 新增/移除了对外依赖
- 改变了业务流程或规则
- 新增了新功能模块

**元数据级更新**（仅更新日期）：

- 仅修改内部实现细节（不影响对外接口）
- 仅修改注释、文档
- 仅修改测试用例
- Bug 修复（不改变接口和行为语义）
- 代码格式调整、变量重命名

**判断方法**：必须阅读 diff 内容，理解修改的语义，而非机械地看行数或文件名。

## Phase 4: 生成预览

对每个受影响的文档，生成更新预览：

1. **元数据级更新预览**：
   - 显示：当前日期 → 新日期
   - 格式：`> 最后校验：2026-02-26` → `> 最后校验：2026-02-27`

2. **内容级更新预览**：
   - 显示：当前模块契约内容
   - 分析：修改了什么，对契约的影响
   - 建议：新的契约内容

3. **新建 MODULE.md 预览**：
   - 显示：将要创建的完整文档内容
   - 基于修改的代码分析模块职责

4. **删除 MODULE.md 预览**：
   - 显示：将要删除的文档路径

汇总所有变更，按类型分组展示。

## Phase 5: 自动执行决策（无确认）

展示预览后，直接进入执行阶段，默认规则如下：

- 元数据级更新：全部执行
- 内容级更新：全部执行
- 缺失文档（目录不存在 MODULE.md）：自动创建
- 删除文档（目录已删除）：自动删除对应 MODULE.md

**禁止使用 `question` 工具询问是否执行。**

## Phase 6: 执行更新

根据自动执行决策直接执行：

### 元数据级更新

使用 `apply_patch` 工具，仅更新日期行：

```
> 最后校验：YYYY-MM-DD
```

### 内容级更新

1. 读取当前 MODULE.md
2. 分析代码修改对契约的影响
3. 使用 `apply_patch` 更新契约内容
4. 更新日期标记

### 新建 MODULE.md（自动创建缺失文档）

使用 `apply_patch` 工具创建文档，包含：

- 可信度标记（当前日期）
- 模块名称（基于目录名）
- 模块契约模板（基于代码分析填充）

### 删除 MODULE.md（自动清理）

使用 Bash 工具删除文件：

```bash
rm path/to/MODULE.md
```

## 输出格式

完成后输出更新报告：

```
## 文档同步完成

### 已更新
- path/to/module/MODULE.md (元数据级)
- path/to/another/MODULE.md (内容级)

### 已创建
- path/to/new/MODULE.md

### 已删除
- path/to/deleted/MODULE.md

### 已跳过
- 无（默认全部自动执行）
```

## MODULE.md 模板

新建文档时使用以下模板：

```markdown
> 最后校验：{当前日期}
> 校验范围：directory

# {目录名称}

{基于代码分析生成的模块职责描述}

## 模块契约

### 我负责什么

- {基于代码分析的职责}

### 我不负责什么

- {边界说明}

### 上游依赖

- 依赖模块：{分析得出的依赖}
- 依赖原因：{依赖原因}

### 下游使用方

- 使用模块：{分析得出的使用方}
- 使用方式：{使用方式}
```

## 注意事项

1. **遵循 AGENTS.md 规范**：MODULE.md 只描述业务语义，不描述实现细节
2. **跨模块修改**：如果修改影响多个模块的契约，在预览中明确提示
3. **根目录 AGENTS.md**：如果修改影响项目整体架构，提示用户考虑更新
4. **无修改时**：如果工作区干净且没有最新 commit，提示「当前没有检测到修改」
5. **执行策略**：默认自动全量执行，不进行交互确认
